# Implementation architecture

See ADR-001-native-engine.md and ADR-002-cue-transport.md. NativeChannel owns two Qt/FFmpeg decks and emits shared QVideoFrame objects. The operator and output QVideoWidgets consume those frames. Independent Programs own independent players; mirrors do not reopen media. During transitions, one CPU compositor converts/blends frames and shares the result. Outside transitions, the Native output profile forwards frames without application QImage conversion. The optional experimental Lanczos profile adds a bounded CPU image resampler per Program/pixel-size pair, shared by matching mirrors. OutputWindow binds to the selected QScreen and accounts for physical pixels/DPI; see ADR-004-output-resolution.md for measurements and limits.

Cue stores validated In/Out and transition metadata. Each Program has its own PlaylistController, which owns the running-order snapshot captured at launch and prepares one next cue. MAIN offers manual CUT/FADE; EDIT controls applied cue metadata and shares the same Preview decoder. Manual overrides affect only the launch, preserving original transitions in the order snapshot. See ADR-003-main-edit-manual-takes.md. Manual playback holds at Out; sequential playback advances when ready, optionally repeating. Failure blocks advance and preserves the current Program. Preparation awaits duration/seekability and a frame at In. Frames before In and at/after Out are not published. A 10 ms boundary timer also mutes/stops at Out; this has not been qualified for sample/frame-accurate broadcast timing.

Qt multimedia uses native libraries, not HTML video. UI uses Widgets; no WebEngine is linked. Language catalogs are compiled resources. Folder discovery runs through QtConcurrent, returning results to the UI thread.

Optional GPU Lanczos uses original GLSL in QOpenGLWidget. Programs/mirrors share input readback through GpuFrameCache; each output owns two-pass GPU textures at its fitted physical size. The scaled texture stays on the GPU for presentation. Pending updates coalesce to the newest frame. This is an 8-bit SDR path with Native fallback for unsupported metadata/context/resources; it does not replace the CPU transition compositor. Actual GL renderer identity and async filter timers are separate from decoder selection. See ADR-005-gpu-lanczos.md.

Audio controls now multiply the existing native deck envelopes by per-Program master gain and apply local mute/device/monitor gates. QAudioBufferOutput taps feed a bounded stereo 48 kHz ring mixer for network audio and peak meters. Each Program owns a NetworkBus with independent optional NDI/OMT worker senders. Both protocols share frame conversion while sending separate network streams; physical outputs remain separate consumers. Audio/transport reset paths and common timeline timestamps are described in ADR-006-audio-network-outputs.md. No remote command server is introduced.

CueReadiness now owns a generation-bound source/trim proof over muted full-range Preview. It validates file access and duration, seeks a nonzero In and pauses after a decoded video frame in range. Applied range changes, changed files, replaced loads and failures invalidate manual-TAKE readiness. Audio-only checks use backend preparation/seek state rather than decoded-PCM proof. Program decks retain their existing prepare-on-TAKE and sequential preroll paths. See ADR-008-source-readiness-and-diagnostics.md.

NativeChannel records bounded publication timestamps and actual CPU composition samples without converting ordinary native frames. Settings/Engine diagnostics reads those snapshots plus existing network counters at 500 ms while visible. Reports keep unsupported decoder adapter/timing/drop/queue fields as null, distinguish intentional preroll filtering and superseded network video, and expose only a requested CPU/auto mode. Native widget captures do not prove physical delivery; hardware video surfaces can be omitted by QWidget::render in the test environment.


Event output configuration now starts with one logical Program and one display route. UI activation exposes B and extra mirrors only when requested; native destinations reject inactive routes/Programs. Schema 3 persists counts and route sources with schema 1/2 migration. Busy B / open-route removal and show loads are guarded before mutation. See ADR-009-event-output-configuration.md.


Dynamic Programs now allocate extra NativeChannel/PlaylistController/NetworkBus objects on demand and store independent applied playlist models. Mirrors reference a Program without an additional decoder. Schema 4 persists stable Program IDs, names and playlists; schema-3 shared lists migrate to separate copies. MAIN stores the selected model before switching and clears Preview readiness, without stopping live Programs. Removed Program identities do not renumber surviving runtime/settings IDs. Diagnostics and route/panel collections grow dynamically. See ADR-010-dynamic-programs-and-playlists.md. GPU transition composition remains deferred; ISSUE-001 remains open.


MAIN now keeps a shared-frame multiview of every configured Program. Stable-ID tile actions resolve the runtime at activation, preserving identity through middle removals and show reloads. The Outputs inventory separates logical Programs from display routes and adds a closed route for a selected Program without opening screens or starting network senders. See ADR-011-multiview-and-routing-inventory.md.
